# 유란노트·유란사진 회귀 검증

이 작업은 기존 오류 재검사, 사진 읽기·동기화 개선, 메뉴 정리 및 표시 개선을 위한 격리 브랜치 작업입니다. 실제 사용자 재고·기기 사진·인증정보를 읽거나 변경하지 않았습니다.

## 소스와 실행 위치

- 기준: `selfness-byte/yuran-android-build@8681f4d1c15822c0d38a0d7efc33540d8692508e`.
- 현재 배포된 QA 앱 소스는 `6d328f13840d4d1d1315b495d9da900094507228`; 이후 기준 커밋까지 변경은 게시 도구 3파일뿐입니다.
- 선택한 cloud checkout은 환경 시작에 실패했습니다. 로컬 checkout/폰 연결을 확인했다고 주장하지 않습니다. 승인된 GitHub 소스와 격리 브랜치의 Actions runner로 검사했습니다.
- 작업 브랜치: `codex/yuran-menu-sync-update-20261012`. 정식 앱 저장소와 자료 형식은 별개입니다.
- 수정 후보 버전: 유란노트 QA 1.17.2 (24), 유란사진 QA 1.4.1 (7). 패키지명과 데이터 형식은 기존 QA 계열을 유지합니다.
- 새 검증 workflow는 읽기 전용 권한으로 synthetic tests와 unsigned APK 컴파일만 수행합니다. 설치·릴리스 게시 작업은 없습니다.

## 확인된 결함과 검사

| 결함 | 자동 검사 | 실제 기기에서 추가 확인 |
| --- | --- | --- |

| 기존 상품 사진이 새입고 라벨로 자동 교체될 위험 | 같은 owner target resolver의 read-only preview, aliases/색상 규칙, generation/revision/work 충돌 검사 | 기존 사진/새 사진 비교 화면과 명시적 교체 |
| 취소·완료 때 파일 권한 해제 순서 문제 | durable queue publication 실패/불확실성 때 해제 0회, 두 mode 공통 권한 생명주기 규약 | Android 문서 제공자·프로세스 종료 뒤 파일 재개 |
| 실시간 조회 결과가 보관되지 않음 | 원본 entry ID에 제한된 결과 저장, 늦게 도착한 결과가 다음 촬영 화면을 덮지 않는 검사 | 연속 촬영 중 뒤늦은 조회 응답과 저장 결과 재열기 |

모든 자동 검사 입력은 합성값입니다. JVM 검사와 소스 검토가 Android 카메라·OCR 엔진·ContentProvider·화면 생명주기의 실기기 검증을 대신하지 않습니다.

## 화면 변경과 OCR 범위

유란노트·유란사진에 아이보리 배경, 골드 강조, 네이비 글자, 둥근 카드·버튼 및 누름/비활성 상태를 적용했습니다. 라벨 촬영 버튼의 대비와 터치 높이를 정리했습니다. 사진 홈은 라벨 촬영/재고조회 연속 촬영/새입고 세 진입을 유지하며, 새입고에는 카메라 연속 촬영·사진 파일 읽기·남은 사진 이어서 처리만 상시 표시합니다. 과거 대기 자료는 이어서 처리 안에서 복구합니다. 실제 기기에서 화면을 렌더링하거나 큰 글꼴을 측정하지는 못했습니다.

OCR는 기존 Chinese/Latin 번들 모델과 의존성 잠금을 유지합니다. 한국어 전용 모델로의 교체는 기존 한자 라벨 인식을 잃을 수 있어 포함하지 않았습니다. 따라서 한글 자체의 인식 품질 향상을 완료했다고 주장하지 않습니다. 이번 변경은 잘못된 수량 결합·부분 자동 입고 방지, 3072px/4MP 이내 디코딩, 불완전한 파일의 회전 재시도, 미인식 사진 보관에 해당합니다.

회전마다 새 비트맵을 만들지 않습니다. 네이티브 처리가 끝나지 않은 경우 단일 비트맵과 파일 OCR gate를 유지합니다. 12초는 디코딩 이후 모델 생성과 OCR 대기에 공유되는 예산이며 파일 디코딩이나 바코드 CPU 처리를 강제로 중단하는 절대 제한은 아닙니다. 읽기 권한·파일 손상 오류는 OCR 미인식과 구분합니다.

## 합성 기기 시나리오

개인 자료를 가져오지 않은 별도 시험 기기/프로필에서 다음을 확인해야 합니다.

1. 합성 `QA100 / WHITE / M8 L5 XL8` (합계 21), `QA101 / WHITE / S3 M4 L4 XL5` (16), `QA102 / GREY / S21 M10 L16 XL10` (57)을 이미지로 만들어 파일 읽기.
2. 가격 59000, 호칭 95(M), 사이즈 목록 S-M-L-XL을 수량으로 더하지 않는지 확인. 부분 불확실성은 사진 전체가 검토로 남아야 합니다.
3. 문자 없는 이미지, 90°/180° 회전 이미지, 흐린 이미지, 정상 이미지를 연속으로 선택. 읽을 수 있는 미인식 사진은 검토에 남고 다음 장은 진행되어야 합니다. 권한/파일 손상은 성공으로 표시하면 안 됩니다.
4. 수량 확인 직후/사진 원격 저장 직후/로컬 ACK 직후 앱 종료 후 재개. 수량은 한 번만 반영되고 기존 요청 결과를 확인해야 합니다.
5. 기존 상품 사진이 있는 품번에 입고할 때 사진을 자동 교체하지 않는지, 명시 교체 확인 후에만 변경되는지 확인.
6. 재고 조회 중 빠르게 다음 라벨을 비추어 이전 조회 결과가 현재 화면을 덮지 않는지 확인.
7. 홈 메뉴, 라벨 촬영, 새입고 3개 진입을 확인. ‘남은 사진 이어서 처리’ 안에서 과거 lookup/intake 대기열·미확정 항목·기존 수동 사진 pending에 접근할 수 있어야 합니다.
8. Galaxy S24 Ultra에서 초점, 인식 시간, 옷 사이즈, 완료음, 연속 촬영을 확인. 화면 회전·200% 글꼴에서도 종료/재개 버튼에 접근할 수 있어야 합니다.
9. 합성 사진 포함 작업 완료→앱 재시작→엑셀/PDF 생성→PC Excel 표시. 실제 USB 프린터와 LAN 인쇄 수신 앱 시험은 이 변경의 실행 범위에 포함되지 않습니다.

## 재실행

자동 검사는 `cloud/test-regressions.sh existing|note|sync|ocr`, `python3 cloud/test-note-refresh.py`, `python3 -m unittest discover -s cloud/tests -p 'test_*.py' -v`입니다. JDK 17 및 Python이 필요합니다. APK 컴파일 절차는 `.github/workflows/yuran-menu-sync.yml`에 고정되어 있습니다. 모든 job의 성공과 정확한 source SHA를 함께 확인합니다.

아스트라 울트라는 수량·사진 요청/복구, owner target API, 노트 완료 처리/입력 갱신, 메뉴·UI, 패키징 및 OCR 통합 소스를 독립 검토했습니다. 추가 발견 사항은 회귀 검사 후 수정했습니다. 정적 검토와 자동 검사 통과를 실기기 설치 가능 판정으로 대신하지 않습니다.

## 설치와 자동 업데이트 차단 요인

기존 QA 게시 도구는 매 빌드 임시 서명키를 만들고 삭제했습니다. 현재 작업에서 기존 설치본 서명키를 확보하거나 복구한 증거는 없습니다.

수정한 `cloud/package-qa.py`는 기존 signer와 증가한 버전 코드, 두 APK 검증을 요구하며 새 임시 키로 대체하지 않습니다. 비밀번호는 환경변수 참조로만 전달하고 도구 출력을 그대로 오류로 노출하지 않습니다. 자세한 조건은 [qa-signing-gate.md](qa-signing-gate.md)를 참조하세요.

기존 키를 안전한 빌드 환경에 제공할 경로가 확인되기 전에는 이 변경을 기존 폰에 덮어쓸 수 있다고 안내하면 안 됩니다. 자동 다운로드·설치 모듈은 구현되지 않았습니다. Android PackageInstaller 조건과 사용자 승인 fallback을 포함한 실제 updater 구현·시험도 남아 있습니다. 앱 삭제/재설치, 정식 앱으로의 강제 전환, 데이터 이관은 수행하지 않았습니다.
